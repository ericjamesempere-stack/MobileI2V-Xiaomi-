# KARMA ONE — real image studio, 2026-11-16

This extends the existing Godot app, on its existing work branch.

## User flow

1. Import a reference photo OR enter a character description and create a reference with Z-Image-Turbo.
2. Choose original style, cartoon, manga, anime, 3D-rendered appearance, or cinematic appearance.
3. Enter a story and choose 2–24 key drawings per batch. Each drawing is newly generated by a Qwen Image Edit Rapid public service. The original reference is supplied on every call and the preceding accepted drawing is supplied for continuity.
4. Review the drawings, approve them, then use the existing native MP4 exporter. Sparse key drawings alone do not establish fluid animation.
5. Repeating a request with the same reference/story/style/count/duration reuses completed cached PNGs. Failed calls preserve completed drawings. The exact-reference action loads the saved reference unchanged and makes no model call.

## Real inference evidence

- Text → image: `mrfakename/Z-Image-Turbo`, `/generate_image`, real anonymous request succeeded, 512×512, seed 1234; about 24 seconds including networking/queue.
- Reference → four-pose sheet: `prithivMLmods/Qwen-Image-Edit-2511-LoRAs-Fast`, `/check_safety` then `/edit_image`, real request succeeded; about 46 seconds. Same orange fox and blue jacket, standing/running/falling/kneeling. Inspected visually.
- Godot → same edit API → single new running pose: actual Godot 4.5.2 HTTP request succeeded and saved a valid PNG. This tests the native app's HTTP adapter, not Android hardware.
- Official unaccelerated Qwen demo was rejected because its requested GPU duration (360 seconds) exceeded the service limit. It is not the bundled production endpoint.
- Godot text creation reached the live service but the anonymous quota was then exhausted; its success path is not yet verified end to end in Godot. Optional Hugging Face token entry is supported through the existing masked token field, is not persisted in the project JSON, and has not been tested with a real account.
- Protocol tests cover normal completion, CRLF, service errors and malformed responses. Headless app startup passed after UI changes.

## Limits

Public services are third-party, quota-limited and can change schemas, models, availability or authorization. No free unlimited GPU access is asserted. No payment or credential is bundled. Images and instructions are sent to the named services when the user selects a remote IA action; the interface states this.

The character's identity, clothing and geometry are model instructions, not guarantees. Only the cartoon/original fox example was inspected; manga, anime, 3D appearance, cinematic appearance, realistic human identity and long temporal continuity remain unvalidated. A 3D-rendered image is a raster image, not an editable 3D mesh or rig. The exact-reference action guarantees reuse of the saved image, not arbitrary pixel-identical regeneration by a model.

The UI key-drawing count is separate from MP4 fps. Long films require multiple batches and many well-spaced intermediate poses; no five-minute neural film has been tested. No optical flow or neural in-between generation is implied by the keyframe feature.

Android gallery, device network connectivity, final encoder and this UI must still be tested on Xiaomi 14T Pro. Linux inference is not a physical-device test.
