# ComfyUI: reference image + OpenPose + IP-Adapter Plus

This is an **unverified, editable API-format starting workflow**, not a bundled inference engine. It uses SD 1.5, an OpenPose ControlNet and IP-Adapter Plus to produce *new* pose-conditioned images rather than moving the source photo as a flat texture. Actual fidelity depends on compatible model files and GPU inference.

## Requirements

- ComfyUI installed with the **ComfyUI_IPAdapter_plus** custom nodes.
- A compatible SD 1.5 checkpoint in `models/checkpoints/`, named `v1-5-pruned-emaonly.safetensors` in the template.
- A compatible SD 1.5 OpenPose ControlNet in `models/controlnet/`, named `control_v11p_sd15_openpose.pth` in the template.
- IP-Adapter Plus SD 1.5 weights and matching CLIP Vision encoder installed according to the custom node documentation.
- A GPU capable of running the chosen models. **No GPU, models, free unlimited hosted endpoint, or HTTPS proxy is supplied by this repository.**

Use `backend/workflows/sd15_ipadapter_openpose_api.json` and configure:

```sh
export MOBILEI2V_API_TOKEN='your-private-long-token'
export COMFYUI_URL='http://127.0.0.1:8188'
export COMFYUI_WORKFLOW='backend/workflows/sd15_ipadapter_openpose_api.json'
export COMFYUI_REFERENCE_NODE=2
export COMFYUI_POSE_NODE=3
export COMFYUI_PROMPT_NODE=4
export COMFYUI_OUTPUT_NODE=13
export COMFYUI_REQUIRE_IDENTITY_ADAPTER=1
uvicorn backend.comfyui_pose_bridge:app --host 127.0.0.1 --port 7862
```

The Android app requires an authenticated **HTTPS** reverse proxy to reach the bridge. Keep ComfyUI itself on localhost. The template deliberately does **not** use `COMFYUI_PREVIOUS_NODE`: adding a previous-frame LoadImage without a suitable conditioning path would be misleading. The original reference image remains connected to IP-Adapter on every frame; the pose guide reaches ControlNet. For temporal consistency, a real previous-frame conditioning workflow still needs to be designed and tested.

**Important:** the pose guide generated by the current Godot app is a stylized drawing, not necessarily the OpenPose skeleton-map format expected by `control_v11p_sd15_openpose.pth`. Before claiming working inference, verify the guide format and adjust the preprocessor/model accordingly. This template has not yet been run on an actual GPU, and no character-identity or movement-quality claim is made.

References: https://github.com/cubiq/ComfyUI_IPAdapter_plus and https://github.com/Comfy-Org/workflow_templates .
